## Установка

Нужны Python 3.10+, Bash, curl и tar на macOS или Linux. Git, зависимости pip и фоновые службы не нужны.

```sh
curl -fsSL https://raw.githubusercontent.com/andre487/MegaProxyTools/main/install.sh | bash
proxy487ctl import /path/to/MegaProxy.json
proxy487ctl list
proxy487ctl choose
proxy487 curl https://example.com
noproxy487 curl https://example.com
```

Для обновления повторите ту же команду: настройки сохраняются. Установщик скачивает
HTTPS-архив во временный каталог и удаляет его после установки. Git не используется.
Добавьте `~/.local/bin` в PATH. Другой префикс можно задать так:

```sh
curl -fsSL https://raw.githubusercontent.com/andre487/MegaProxyTools/main/install.sh | PREFIX="$HOME/tools" bash
```

`MEGAPROXY_TOOLS_REF` выбирает ветку, тег или коммит архива (по умолчанию `main`);
задавайте переменную на стороне `bash`. При необходимости другой версии самого
установщика укажите тот же ref в URL. Из локального checkout по-прежнему работает
`./install.sh` без сети, включая `PREFIX=/path ./install.sh`.
Команды устанавливаются в `PREFIX/bin`, библиотека и схемы — в
`PREFIX/lib/megaproxy-tools`. После обновления повторите установку. Для удаления
удалите три команды и каталог библиотеки; настройки сохраняются. Скрипты можно
запускать прямо из полного checkout.

### Установка из Git

```sh
./install.sh --git
INSTALL_FROM_GIT=1 ./install.sh
curl -fsSL https://raw.githubusercontent.com/andre487/MegaProxyTools/main/install.sh | bash -s -- --git
curl -fsSL https://raw.githubusercontent.com/andre487/MegaProxyTools/main/install.sh | INSTALL_FROM_GIT=1 bash
```

Для этого режима нужен Git. Из репозитория устанавливаются абсолютные ссылки
в `PREFIX/bin` на скрипты текущего checkout; изменения скриптов и библиотеки сразу
действуют. Текущий репозиторий не обновляется и не переключается. При запуске через
pipe репозиторий клонируется в `PREFIX/src/MegaProxyTools`, по умолчанию
`~/.local/src/MegaProxyTools`. Повторный запуск через pipe получает
`MEGAPROXY_TOOLS_REF` (по умолчанию `main`), переключается на него и обновляется только
fast-forward. Локальные изменения или чужой каталог исходников останавливают установку.
Библиотека читается из checkout: сохраняйте его, пока используете ссылки.
Повторная обычная установка заменяет ссылки самостоятельными копиями файлов.

### Windows

Установка или обновление из Windows PowerShell 5.1+ или PowerShell 7:

```powershell
irm https://raw.githubusercontent.com/andre487/MegaProxyTools/main/win/install.ps1 | iex
```

Загрузчик скачивает архив, вызывает `install.cmd` и удаляет временные файлы.
Повторный запуск обновляет инструменты, сохраняя настройки. Для постоянного Git checkout:

```powershell
$env:INSTALL_FROM_GIT = '1'
irm https://raw.githubusercontent.com/andre487/MegaProxyTools/main/win/install.ps1 | iex
Remove-Item Env:INSTALL_FROM_GIT
```

Этот режим клонирует проект в `PREFIX\src\MegaProxyTools` и создаёт обёртки на него.
Повторный запуск получает `MEGAPROXY_TOOLS_REF` (по умолчанию `main`) и обновляет
checkout только через fast-forward. Локальные изменения, чужой checkout или
расхождение истории останавливают обновление. `MEGAPROXY_TOOLS_REF` также выбирает
версию обычного архива; для другой версии самого загрузчика укажите тот же ref в URL.

Скачайте и распакуйте полный репозиторий или клонируйте его. В PowerShell или cmd:

```powershell
.\install.cmd
# Запуск прямо из текущего Git checkout вместо копирования:
.\install.cmd --git
```

Нужен Python 3.10+. Установщик проверяет `python`, затем `py -3`; если подходящего
Python нет, выводит команду установки через winget. Для `--git` также проверяется
Git и выводится команда установки при его отсутствии. Текущий checkout не обновляется
и не переключается. Обычный режим копирует скрипты и библиотеку, а `--git` создаёт
обёртки с путями в checkout: изменения сразу действуют. В этом режиме не перемещайте
и не удаляйте checkout.

По умолчанию установка идёт в `%LOCALAPPDATA%\MegaProxyTools`; переменная `PREFIX`
задаёт другой каталог. Установщик добавляет `bin` в пользовательский PATH без прав
администратора. После установки заново откройте терминал. Обёртки `.cmd` находят
Python через PATH; менять политику выполнения PowerShell не нужно.
Для обновления или переключения режима повторите установку: настройки сохраняются.
Для удаления удалите каталог установки и его запись в пользовательском PATH.
В PowerShell используйте `curl.exe`, чтобы не вызывать алиас Windows PowerShell.
Права POSIX вроде 0600 не задают Windows ACL: доступ к конфигу ограничивается
средствами Windows.

## Конфигурация

Каталог настроек — `$XDG_CONFIG_HOME/megaproxy-tools`, по умолчанию
`~/.config/megaproxy-tools`. Пустой или относительный `XDG_CONFIG_HOME` означает дефолт.

Основной файл — `config.json` формата
[MegaProxyConfig v8](https://github.com/andre487/MegaProxyConfig).
Профили имеют стабильные ID, выбор хранится в `activeProfileId`.
Новые каталоги создаются с правами 0700, JSON записывается атомарно с правами 0600.
Файл содержит пароли: не публикуйте его.

`default.env` остаётся отдельным локальным файлом. `proxy487ctl init` создаёт
каталог настроек. Затем нужен импорт: схема требует непустой список профилей.

## Управление и импорт

```sh
proxy487ctl import /path/to/MegaProxy.json
cat /path/to/MegaProxy.json | proxy487ctl import -
proxy487ctl list
proxy487ctl choose                   # интерактивный выбор
proxy487ctl choose 2                 # номер
proxy487ctl choose stable-profile-id # ID
proxy487ctl choose proxy.example.com # уникальный hostname
```

Список отмечает текущий профиль звёздочкой, показывает название и ID, скрывает логины
и пароли. Если hostname совпадает у нескольких профилей, выбирайте по номеру или ID.
Без сохранённого выбора используется первый профиль.

Принимается только [MegaProxy JSON v8](https://github.com/andre487/MegaProxyConfig)
с идентификатором схемы `net.megaproxy487.config` или `dev.megaproxy.config`.
Кодировка — UTF-8, допустим BOM. Лимит — 1 МиБ и 1000 профилей. Ручной импорт и
обновление подписки используют одинаковые формат и проверку. Другие структуры JSON,
старые версии конфигурации и текстовые списки proxy отклоняются.

Проверка выполняется офлайн по закреплённым схемам MegaProxyConfig средствами stdlib.
Коммит источника и хеши — в `lib/megaproxy-tools/config-schema/schema-lock.json`.
Валидатор поддерживает ключевые слова закреплённой схемы, а не произвольный JSON Schema.

### Правила слияния

MegaProxy JSON обновляет совпадающие ID и добавляет новые. Порядок существующих
профилей сохраняется, отсутствующие в импорте профили не удаляются. Текущий выбор,
включая неявный выбор первого профиля, сохраняется. При первом импорте используется
совместимый `activeProfileId`. Импорт не запускает команды и не устанавливает соединение.

Отсутствующий пароль сохраняет старое значение только при неизменных типе,
нормализованном hostname, порте и логине. Явный пустой пароль очищает его. Другой
endpoint или аккаунт никогда не наследует старый пароль. Неполные credentials SOCKS5
можно сохранить; для запуска нужны оба значения либо оба пустые.
Дубли ID, отсутствующий active ID и некорректные известные поля отклоняются.
При ошибке существующий JSON сохраняется. Несовместимые профили пропускаются с
предупреждением; неподдерживаемые настройки платформ и неизвестные поля удаляются
с уведомлением. Явный корневой `routing.bypassLocalNetworks` применяется, при
отсутствии поля сохраняется локальное значение.

### Поддержка протоколов

Исполняются HTTPS и SOCKS5. SOCKS5 передаётся дочерней команде как `socks5h://` для
разрешения DNS через proxy; программа должна это поддерживать. HTTPS сохраняет TLS
до proxy. SSH, Jump, MASQUE и профили с отключённой проверкой сертификата пропускаются
явно и не преобразуются в другие протоколы. HTTP отсутствует в переносимом контракте
MegaProxyConfig; нужен HTTPS endpoint.
TLS fingerprints, предпочтение HTTP/3, DNS, knock, правила приложений/доменов,
браузерные настройки не реализованы и вызывают уведомление
при импорте.

## Подписка на конфигурацию

Импортируйте MegaProxy JSON с корневым объектом `subscription`:

```json
"subscription": {
  "url": "https://configs.example.com/MegaProxy.json",
  "fallbackUrls": ["https://backup.example.com/MegaProxy.json"],
  "username": "reader",
  "password": "example",
  "intervalMinutes": 60,
  "enabled": true
}
```

Обязателен только `url`; авторизация и резервные адреса необязательны. Импорт сохраняет
подписку и сразу проверяет её, если проверка не отключена флагом. Затем `proxy487` и
`proxy487ctl` проверяют просроченную подписку перед выполнением команды. Справка и
некорректные вызовы сеть не используют. Фоновых служб нет. Общий лимит для обеих утилит
и параллельных процессов — не чаще раза в час, включая неудачные попытки. Больший
`intervalMinutes` учитывается, меньший ограничивается 60 минутами. `enabled: false`
приостанавливает проверки.

```sh
proxy487 --no-config-sync curl https://example.com
proxy487 --no-config-sync КОМАНДА АРГУМЕНТ
proxy487ctl --no-config-sync list
proxy487ctl --no-config-sync import MegaProxy.json
```

Флаг идёт перед командой/подкомандой и не передаётся дочернему процессу. Такой же аргумент
после имени дочерней команды принадлежит ей. `noproxy487` подписку не проверяет.
Логи идут в stderr до запуска команды: номер успешного источника, количество добавленных,
изменённых и удалённых профилей, смена выбранного профиля, настроек локального обхода и
источников. Пароли, токены, URL подписки и тела ответов не выводятся. Ошибка загрузки,
проверки или сохранения оставляет рабочую конфигурацию; команда запускается со старыми
настройками после сообщения об ошибке.

Загрузка использует унаследованные сетевые/proxy-переменные окружения. Нужен HTTPS с
проверкой сертификата; редиректы запрещены. Основной и максимум семь резервных URL
проверяются по порядку до первого успешно применённого снимка. Ответ — HTTP 200,
UTF-8, максимум 1 МиБ. Сжатие не запрашивается и не принимается. Таймаут сокета —
10 секунд, бюджет чтения тела — 20 секунд с проверкой между чтениями.
Заголовки клиента: `X-MegaProxy-Client: megaproxy_tools` и версия разработки
`X-MegaProxy-Version: 0+unreleased`. Необязательная Basic Auth кодируется в UTF-8
и отделена от авторизации самого proxy.

Снимок заменяет профили подписки, удаляя исчезнувшие из неё; отдельно добавленные
профили сохраняются. Сопоставление выполняется по стабильным ID MegaProxy. Конфликт ID с отдельным локальным профилем отклоняет источник.
Выбор сохраняется, пока профиль существует; при удалении выбирается совместимый
`activeProfileId` снимка, затем первый профиль снимка. Правила сохранения паролей
совпадают с ручным импортом.

Импорт с корневой подпиской передаёт ей профили этого импорта. Если конфиг изменён
вручную и состояния подписки ещё нет, первоначально ей принадлежат все его профили.
Отсутствие `subscription` при ручном импорте сохраняет подписку, явный null удаляет её.
Пропущенный пароль подписки сохраняется только для прежних нормализованного основного
URL и логина. Загруженный документ может заменить основной и резервные URL, сохраняя
локальные credentials, интервал и паузу; отсутствующая или null-подписка в снимке
сохраняет источники. Доверяйте владельцу источника: он может назначить новые URL,
которые также получат локальные credentials.

Время попыток, принадлежность профилей и последние успех/ошибка хранятся отдельно,
с приватными правами, в `$XDG_STATE_HOME/megaproxy-tools/config-sync-<хеш-пути-конфига>.json`,
по умолчанию — `~/.local/state/megaproxy-tools/`. Пустой/относительный `XDG_STATE_HOME`
означает дефолт. Блокировка координирует импорт, выбор и обновление; на время ожидания
интерактивного ввода она освобождается.

## Запуск команд

`proxy487 [--no-config-sync] КОМАНДА [АРГУМЕНТЫ]` назначает HTTP_PROXY, HTTPS_PROXY, ALL_PROXY,
WS_PROXY и WSS_PROXY в обоих регистрах только дочернему процессу.
Существующий `no_proxy` приоритетнее `NO_PROXY`, включая пустое значение.
Иначе `routing.bypassLocalNetworks` (по умолчанию true) задаёт обход localhost,
loopback и 192.168/16; false означает пустой список. Поддержка CIDR зависит от клиента.
Поддержка WS_PROXY/WSS_PROXY также зависит от программы.

`proxy487` также задаёт `NODE_USE_ENV_PROXY=1` по умолчанию. Значение из окружения
или `default.env` имеет приоритет: например, `NODE_USE_ENV_PROXY=0` отключает флаг.
Node.js читает его при запуске; явно заданные агенты/dispatchers могут переопределять
это поведение. `noproxy487` удаляет флаг вместе с переменными прокси.

| Среда/клиент | Дополнительная настройка |
| --- | --- |
| [Node.js](https://nodejs.org/en/learn/http/enterprise-network-configuration) | `NODE_USE_ENV_PROXY=1`: `fetch` с 22.21.0/24.0.0, `http`/`https` с 22.21.0/24.5.0. Старым версиям нужна настройка приложения. Встроенная поддержка принимает HTTP/HTTPS-прокси, но не SOCKS. |
| [Python urllib](https://docs.python.org/3/library/urllib.request.html#urllib.request.ProxyHandler), [Requests](https://requests.readthedocs.io/en/latest/user/advanced/#proxies) | Читают переменные прокси по умолчанию, дополнительный флаг не нужен. Это не распространяется на все HTTP-клиенты Python. |
| [Go net/http](https://pkg.go.dev/net/http#DefaultTransport) | Стандартный транспорт читает переменные прокси, дополнительный флаг не нужен. Пользовательский транспорт может работать иначе. |
| [Современный .NET HttpClient](https://learn.microsoft.com/en-us/dotnet/api/system.net.http.httpclient.defaultproxy) | Прокси по умолчанию учитывает окружение. Дополнительный флаг не нужен; настройки обработчика могут переопределять поведение. |
| [Bun fetch](https://bun.com/docs/runtime/networking/fetch) | Читает переменные прокси по умолчанию, дополнительный флаг не нужен. |
| [Java](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/net/doc-files/net-properties.html) | Обычно нужны свойства JVM вроде `http.proxyHost`/`https.proxyHost` или настройка клиента. `java.net.useSystemProxies=true` включает настройки ОС, а не общее преобразование наших переменных окружения. |

Поддержка протоколов, авторизации и правил обхода зависит от конкретного клиента.
Обёртка не может заставить программу учитывать переменные прокси, если та их игнорирует.

`noproxy487` удаляет эти переменные и NO_PROXY в любом регистре. Настройки самого
приложения, системные proxy и VPN остаются действовать. Аргументы, сигналы и код
возврата сохраняются через exec. Родительская оболочка не меняется.
`proxy487ctl --help` и `--help` подкоманд работают без пользовательской настройки.
`proxy487` распознаёт только ведущий `--no-config-sync`; инициализация и справка — в `proxy487ctl`.

Успешный HTTPS-запрос не подтверждает работу WebSocket. Не публикуйте URL с паролями
и дампы окружения. Не заменяйте `https://` на `http://`, если endpoint не обслуживает
открытый HTTP.

## Диагностика и опциональное измерение скорости

```sh
proxy487ctl diagnose
proxy487ctl --no-config-sync diagnose
proxy487ctl diagnose --speed --megabytes 10
proxy487ctl diagnose --speed --megabytes 25 --compare
proxy487ctl diagnose --http-version 1.1
proxy487ctl diagnose --http-version 2
```

Сначала выводятся название, ID и адрес активного профиля без логина и пароля.
По умолчанию проверяется только выбранный proxy: HTTPS-запрос к example.com,
сертификаты, тайминги DNS/TCP/установления соединения, внешний IP и страна.
Для HTTPS проверяется CONNECT; SOCKS5 разрешает имя целевого сервера на стороне proxy.
Сначала используется Cloudflare trace, затем резервные провайдеры IP/страны,
как в AndroidMegaProxy. Ответы проверяются перед выводом. Отсутствие страны не считается
ошибкой; ошибка HTTPS или получения IP даёт код возврата 1.

`--speed` добавляет три пробы задержки (медиана TTFB после установки соединения),
загрузку и отправку через Cloudflare. `--megabytes` — 10, 25 или 50 **десятичных МБ
в каждом направлении**, по умолчанию 10. Без `--speed` больших передач нет.
`--compare` явно добавляет прямой маршрут без унаследованных proxy-переменных.
Со скоростью это удваивает объём: по умолчанию суммарно 40 МБ. Профиль и настройки
измерениями не меняются. Обычная проверка подписки при запуске остаётся; глобальный
`--no-config-sync` отключает её.

Нужен системный curl 8.4+ для ограничения объёма, с TLS и HTTPS-proxy для HTTPS-профилей.
HTTP/2 зависит от сборки curl. `--http-version 2` предпочитает HTTP/2 с возможностью
отката curl к HTTP/1.1; `auto` оставляет выбор curl. Выводятся реально наблюдавшиеся
версии HTTP/TLS. Проверяются TCP HTTPS/SOCKS5; тестов Android VPN, QUIC/HTTP3,
UDP relay и TLS fingerprints здесь нет.

Credentials передаются curl через stdin, а не аргументы процесса. curlrc и
унаследованные proxy/bypass-переменные отключены, поэтому успешная проверка не может
незаметно обойти выбранный proxy. Проверка сертификатов включена, редиректы запрещены.
Обычные ответы ограничены 16 КиБ; download должен совпасть с выбранным размером,
upload отправляет ровно столько нулевых байтов. Таймаут соединения — 10 секунд,
общий таймаут запроса — 10 секунд, для каждой большой передачи — 120 секунд.
Приватные временные файлы удаляются. Сырые ошибки curl и тела ответов не печатаются;
выводится только безопасная категория ошибки/HTTP-статус. Код возврата: 0 при успехе,
1 при ошибке проверки, 130 при прерывании.

## Необязательные переменные окружения

Локальный файл `~/.config/megaproxy-tools/default.env` задаёт значения для `proxy487`:

```dotenv
GODEBUG=http2client=0
```

Формат: буквальные строки `NAME=VALUE`; пустые строки и отдельные комментарии `#`
пропускаются. Пробелы по краям удаляются. Кавычки, `export`, подстановки и команды
shell не интерпретируются. Существующее окружение приоритетнее файла; адреса proxy
берутся из выбранного профиля. Некорректная запись останавливает запуск.
Этот файл не входит в переносимый JSON, не импортируется и не читается `noproxy487`.
Используйте права 600.

## Разработка

```sh
python3 -m unittest discover -s tests -v
sh -n install.sh
uvx --from ruff==0.17.3 ruff check .
uvx --from ruff==0.17.3 ruff format --check .
```

На Windows запускайте общий набор тестов так:

```powershell
python -m unittest discover -s tests -v
```

Проверяются команды по имени в cmd и PowerShell, передача аргументов и кодов
возврата, обычная установка и `--git`, обновление PATH и межпроцессная блокировка.
Тесты используют временные каталоги и подменяют запись в реестр: пользовательский
PATH не меняется. Проверки POSIX-установщика на Windows пропускаются.
CI запускает тесты на Windows, Linux и macOS с Python 3.10 и 3.14.
