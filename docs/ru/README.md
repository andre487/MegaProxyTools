## Установка

Нужны Python 3.9+, Bash, curl и tar на macOS или Linux. Git, зависимости pip и фоновые службы не нужны.

```sh
curl -fsSL https://raw.githubusercontent.com/andre487/MegaProxyTools/main/install.sh | bash
proxy487ctl import /path/to/MegaProxy.json
proxy487ctl list
proxy487ctl choose
proxy487 curl https://example.com
noproxy487 curl https://example.com
```

Для обновления повторите ту же команду: настройки сохраняются. Установщик скачивает
HTTPS-архив во временный каталог и удаляет его после установки. Git не используется.
Добавьте `~/.local/bin` в PATH. Другой префикс можно задать так:

```sh
curl -fsSL https://raw.githubusercontent.com/andre487/MegaProxyTools/main/install.sh | PREFIX="$HOME/tools" bash
```

`MEGAPROXY_TOOLS_REF` выбирает ветку, тег или коммит архива (по умолчанию `main`);
задавайте переменную на стороне `bash`. При необходимости другой версии самого
установщика укажите тот же ref в URL. Из локального checkout по-прежнему работает
`./install.sh` без сети, включая `PREFIX=/path ./install.sh`.
Команды устанавливаются в `PREFIX/bin`, библиотека и схемы — в
`PREFIX/lib/megaproxy-tools`. После обновления повторите установку. Для удаления
удалите три команды и каталог библиотеки; настройки сохраняются. Скрипты можно
запускать прямо из полного checkout. Проверьте `command -v proxy487`: старые копии
из dotfiles раньше в PATH нужно удалить или заменить переходными обёртками.

## Конфигурация и миграция

Каталог настроек — `$XDG_CONFIG_HOME/megaproxy-tools`, по умолчанию
`~/.config/megaproxy-tools`. Пустой или относительный `XDG_CONFIG_HOME` означает дефолт.
Если нового каталога нет, целиком используется старый `~/.proxy487`.
Файлы из разных каталогов не смешиваются.

Основной файл — `config.json` формата
[MegaProxyConfig v8](https://github.com/andre487/MegaProxyConfig).
Профили имеют стабильные ID, выбор хранится в `activeProfileId`.
Новые каталоги создаются с правами 0700, JSON записывается атомарно с правами 0600.
Файл содержит пароли: не публикуйте его.

Если есть только `proxy-list.txt`, первый запуск создаёт из него `config.json`,
сохраняя выбор hostname из `chosen`. Старые файлы остаются резервными копиями;
после миграции используется только JSON. `default.env` остаётся отдельным локальным
файлом. Для переноса старого каталога в XDG убедитесь, что назначения ещё нет,
переместите каталог и установите права 0700 для каталога, 0600 для файлов.

`proxy487ctl init` (аналог `proxy487 --init`) создаёт каталог либо мигрирует старые
настройки. При первом запуске затем нужен импорт: схема требует непустой список.

## Управление и импорт

```sh
proxy487ctl import /path/to/MegaProxy.json
proxy487ctl import /path/to/ProxyList.txt
cat /path/to/FoxyProxy.json | proxy487ctl import -
proxy487ctl list
proxy487ctl choose                   # интерактивный выбор
proxy487ctl choose 2                 # номер
proxy487ctl choose stable-profile-id # ID
proxy487ctl choose proxy.example.com # уникальный hostname
```

Список отмечает текущий профиль звёздочкой, показывает название и ID, скрывает логины
и пароли. Если hostname совпадает у нескольких профилей, выбирайте по номеру или ID.
Без сохранённого выбора используется первый профиль.

Формат определяется по содержимому UTF-8, включая файлы с BOM:

- MegaProxy JSON версий 1–8, включая `dev.megaproxy.config`; запись всегда в версии 8.
- ProxyList и SuperProxy с заголовком `# superproxy:proxylist:v1`: URL с кодированными
  credentials и необязательными query-параметрами `title`/`cc`.
- FoxyProxy JSON (`data`), старые браузерные массивы и объекты `profiles`, включая
  псевдонимы `ssl`/`socks` и поля `host`/`hostname`/`address`.
- ZeroOmega/SwitchyOmega версий 1–2: FixedProfile с одинаковым endpoint и credentials
  для всех протоколов. PAC, переключатели и правила маршрутизации не применяются;
  профили с разными адресами или авторизацией по протоколам пропускаются.

Лимит входных и сохраняемых данных — 1 МиБ и 1000 профилей. Проверка выполняется
офлайн по закреплённым схемам MegaProxyConfig средствами stdlib. Версии 1–7 сначала
нормализуются. Коммит источника и хеши — в
`lib/megaproxy-tools/config-schema/schema-lock.json`. Валидатор поддерживает ключевые
слова закреплённой схемы и не является универсальным JSON Schema API.

### Правила слияния

MegaProxy JSON обновляет совпадающие ID и добавляет новые. Порядок существующих
профилей сохраняется, отсутствующие в импорте профили не удаляются. Текущий выбор,
включая неявный выбор первого профиля, сохраняется. При первом импорте используется
совместимый `activeProfileId`. Импорт не запускает команды и не устанавливает соединение.
Форматы без стабильных ID при каждом ручном импорте создают новые профили.

Отсутствующий пароль сохраняет старое значение только при неизменных типе,
нормализованном hostname, порте и логине. Явный пустой пароль очищает его. Другой
endpoint или аккаунт никогда не наследует старый пароль. Неполные credentials SOCKS5
можно сохранить; для запуска нужны оба значения либо оба пустые.
Дубли ID, отсутствующий active ID и некорректные известные поля отклоняются.
При ошибке существующий JSON сохраняется. Несовместимые профили пропускаются с
предупреждением; неподдерживаемые настройки платформ и неизвестные поля удаляются
с уведомлением. Явный корневой `routing.bypassLocalNetworks` применяется, при
отсутствии поля сохраняется локальное значение.

### Поддержка протоколов

Исполняются HTTPS и SOCKS5. SOCKS5 передаётся дочерней команде как `socks5h://` для
разрешения DNS через proxy; программа должна это поддерживать. HTTPS сохраняет TLS
до proxy. SSH, Jump, MASQUE и профили с отключённой проверкой сертификата пропускаются
явно и не преобразуются в другие протоколы. HTTP из старых форматов пропускается:
такого протокола нет в переносимом контракте MegaProxyConfig; нужен HTTPS endpoint.
TLS fingerprints, предпочтение HTTP/3, DNS, knock, правила приложений/доменов,
браузерные настройки не реализованы и вызывают уведомление
при импорте. ProxyList также не переносит эти настройки.

## Подписка на конфигурацию

Импортируйте MegaProxy JSON с корневым объектом `subscription`:

```json
"subscription": {
  "url": "https://configs.example.com/MegaProxy.json",
  "fallbackUrls": ["https://backup.example.com/MegaProxy.json"],
  "username": "reader",
  "password": "example",
  "intervalMinutes": 60,
  "enabled": true
}
```

Обязателен только `url`; авторизация и резервные адреса необязательны. Импорт сохраняет
подписку и сразу проверяет её, если проверка не отключена флагом. Затем `proxy487` и
`proxy487ctl` проверяют просроченную подписку перед выполнением команды. Справка и
некорректные вызовы сеть не используют. Фоновых служб нет. Общий лимит для обеих утилит
и параллельных процессов — не чаще раза в час, включая неудачные попытки. Больший
`intervalMinutes` учитывается, меньший ограничивается 60 минутами. `enabled: false`
приостанавливает проверки.

```sh
proxy487 --no-config-sync curl https://example.com
proxy487 --no-config-sync -- КОМАНДА АРГУМЕНТ
proxy487ctl --no-config-sync list
proxy487ctl --no-config-sync import MegaProxy.json
```

Флаг идёт перед командой/подкомандой и не передаётся дочернему процессу. Такой же аргумент
после имени дочерней команды принадлежит ей. `noproxy487` подписку не проверяет.
Логи идут в stderr до запуска команды: номер успешного источника, количество добавленных,
изменённых и удалённых профилей, смена выбранного профиля, настроек локального обхода и
источников. Пароли, токены, URL подписки и тела ответов не выводятся. Ошибка загрузки,
проверки или сохранения оставляет рабочую конфигурацию; команда запускается со старыми
настройками после сообщения об ошибке.

Загрузка использует унаследованные сетевые/proxy-переменные окружения. Нужен HTTPS с
проверкой сертификата; редиректы запрещены. Основной и максимум семь резервных URL
проверяются по порядку до первого успешно применённого снимка. Ответ — HTTP 200,
UTF-8, максимум 1 МиБ. Сжатие не запрашивается и не принимается. Таймаут сокета —
10 секунд, бюджет чтения тела — 20 секунд с проверкой между чтениями.
Заголовки клиента: `X-MegaProxy-Client: megaproxy_tools` и версия разработки
`X-MegaProxy-Version: 0+unreleased`. Необязательная Basic Auth кодируется в UTF-8
и отделена от авторизации самого proxy.

Снимок заменяет профили подписки, удаляя исчезнувшие из неё; отдельно добавленные
профили сохраняются. Для канонического JSON используются стабильные ID; старые форматы
сопоставляются по уникальному названию среди профилей подписки, затем по уникальному
типу/hostname/порту. Конфликт ID с отдельным локальным профилем отклоняет источник.
Выбор сохраняется, пока профиль существует; при удалении выбирается совместимый
`activeProfileId` снимка, затем первый профиль снимка. Правила сохранения паролей
совпадают с ручным импортом.

Импорт с корневой подпиской передаёт ей профили этого импорта. Если конфиг изменён
вручную и состояния подписки ещё нет, первоначально ей принадлежат все его профили.
Отсутствие `subscription` при ручном импорте сохраняет подписку, явный null удаляет её.
Пропущенный пароль подписки сохраняется только для прежних нормализованного основного
URL и логина. Загруженный документ может заменить основной и резервные URL, сохраняя
локальные credentials, интервал и паузу; отсутствующая или null-подписка в снимке
сохраняет источники. Доверяйте владельцу источника: он может назначить новые URL,
которые также получат локальные credentials.

Время попыток, принадлежность профилей и последние успех/ошибка хранятся отдельно,
с приватными правами, в `$XDG_STATE_HOME/megaproxy-tools/config-sync-<хеш-пути-конфига>.json`,
по умолчанию — `~/.local/state/megaproxy-tools/`. Пустой/относительный `XDG_STATE_HOME`
означает дефолт. Блокировка координирует импорт, выбор и обновление; на время ожидания
интерактивного ввода она освобождается.

## Запуск команд

`proxy487 [--] КОМАНДА [АРГУМЕНТЫ]` назначает HTTP_PROXY, HTTPS_PROXY, ALL_PROXY,
WS_PROXY и WSS_PROXY в обоих регистрах только дочернему процессу.
Существующий `no_proxy` приоритетнее `NO_PROXY`, включая пустое значение.
Иначе `routing.bypassLocalNetworks` (по умолчанию true) задаёт обход localhost,
loopback и 192.168/16; false означает пустой список. Поддержка CIDR зависит от клиента.
Поддержка WS_PROXY/WSS_PROXY также зависит от программы.

`noproxy487` удаляет эти переменные и NO_PROXY в любом регистре. Настройки самого
приложения, системные proxy и VPN остаются действовать. Аргументы, сигналы и код
возврата сохраняются через exec. Родительская оболочка не меняется.
`--help` работает без пользовательской настройки.

Успешный HTTPS-запрос не подтверждает работу WebSocket. Не публикуйте URL с паролями
и дампы окружения. Не заменяйте `https://` на `http://`, если endpoint не обслуживает
открытый HTTP.

## Необязательные переменные окружения

Локальный файл `~/.config/megaproxy-tools/default.env` задаёт значения для `proxy487`:

```dotenv
GODEBUG=http2client=0
```

Формат: буквальные строки `NAME=VALUE`; пустые строки и отдельные комментарии `#`
пропускаются. Пробелы по краям удаляются. Кавычки, `export`, подстановки и команды
shell не интерпретируются. Существующее окружение приоритетнее файла; адреса proxy
берутся из выбранного профиля. Некорректная запись останавливает запуск.
Этот файл не входит в переносимый JSON, не импортируется и не читается `noproxy487`.
Используйте права 600.
